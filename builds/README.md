# builds/ — the ready-to-use mod

The `.jar` in this folder is **Vantraya Builder**, built from the sources in this repository. This is the file to put in a modpack.

```
vantraya-builder-neoforge-1.21.1-<version>.jar
└─ mod name ─┘ └ loader ┘ └ Minecraft ┘ └ the mod's version (mod_version in gradle.properties)
```

## Install

1. A **NeoForge 1.21.1** instance (Java 21). It is compiled against NeoForge 21.1.176; any 21.1.x should do.
2. Copy the jar into the instance's `mods/` folder — on the client and on the server.
3. *Create New World → World → World Type → **Vantraya***. Dedicated server: `level-type=vantraya_builder:vantraya` in `server.properties`.
4. Then follow **Check that it worked**, below.

**Updating:** delete the old jar from `mods/` first — two versions of one mod stop the game from starting — and create a **new** world; a world keeps what it was made with.

Lithosphere, Still Life, Tectonic and Lithostitched are optional; none of them is needed. How Vantraya Builder works next to them is in [`docs/COMPATIBILITY.md`](../docs/COMPATIBILITY.md).

## Check that it worked

About five minutes, in a **new** world made with *World Type → Vantraya*. Turn **Allow Cheats** on (Game tab): `/vantraya verify` and `/vantraya tp` need it, `/vantraya info` and `/vantraya where` do not.

1. **Is the mod loaded?** Title screen → *Mods* lists *Vantraya Builder 0.1.1*. In the world, `/vantraya info` lists the nine landmarks; *Unknown or incomplete command* means the jar is not loaded (wrong `mods` folder or instance).
2. **Did the world type take?** Press **F3**. You start on the Forgotten Coast, about **x 0, z 2500**, on flat ground near Y 68, and the left column has a line starting **`Vantraya: Forgotten Coast …`** right under the `NoiseRouter` line. *No `Vantraya:` line means the world was not generated by Vantraya.*
3. **Ask the mod.** `/vantraya where` names the landmark you stand in (here *Forgotten Coast*) and the surface height. *This dimension is not generated by the Vantraya world type (it uses …)* means another mod's overworld still won.
4. **The acceptance test.** `/vantraya verify` reads the running generator, not the model. Expect **22 / 22 checks passed - this world matches the specification.** Red lines are failures: send them to me. One rare false alarm is known: the crater-floor check reads a single column, and a cave that opens exactly there fails it.
5. **Look around.** `/vantraya tp <landmark>` takes you to each one (you land 3 blocks above the ground):

| `/vantraya tp …` | x, z | What to expect |
|---|---|---|
| `forgotten_coast` | 0, 2500 | plains / meadow, Y 68–74 |
| `ashen_caldera` | 0, 0 | the crater: an **Obsidian Throne** at the centre (top at Y 92), lava on the crater floor, basalt and eroded badlands, **no water** |
| `cogwork_march` | −2100, 0 | windswept hills / wooded badlands, Y 85–110 |
| `glacial_spine` | 0, −2500 | frozen and jagged peaks, Y 180–279 |
| `gilded_dunes` | 2300, 0 | desert / badlands, Y 75–94 |
| `whispering_fen` | 2000, 2000 | swamp / mangrove, flat at sea level (Y 62–66) |
| `sunken_reach` | −2400, 1600 | warm ocean, sea floor near Y 54 — you drop into the water |
| `hermits_spire` | −1800, −1800 | high ground, Y 140–185 |
| `byzantine_choir` | 1800, −1800 | meadow / cherry grove, Y 110–145 |

Beyond 3550 blocks from the origin lies the **Veil of Salt**: deep ocean, an abyss. Biomes are vanilla's unless you have added other mods' biomes to the role tags.

**If a step fails, send me** a screenshot of F3, the output of `/vantraya where`, and the lines containing `Vantraya` from `logs/latest.log` (launcher → instance folder → `logs`). In that log, `Vantraya: this world's overworld is generated by the Vantraya world type` is the line you want. `Vantraya: a data pack defines its own minecraft:overworld (…) which would replace the Vantraya world type; keeping the Vantraya overworld` is the guard doing its job — and the proof that the override was real.

## Where this jar comes from

* It is built by GitHub Actions (`.github/workflows/build.yml`), which runs **all the tests first** — the specification tests and the ones that start the real game engine — and commits the jar here only if every one of them passed. The commit message of the jar says which source commit it was built from and gives its SHA-256.
* `./gradlew build` does the same on your own machine: it runs the tests, then puts the jar in `builds/` (and in `build/libs/`).
* The build is reproducible: the same sources give the same bytes, so a rebuild of unchanged sources changes nothing in this folder.
* Only **one** jar is kept here, always the newest. Two versions of one mod in `mods/` stop the game from starting.

## Played once so far

The tests prove the landmarks, elevations, climate tiers and the surface table. The one real game so far (a pack with Lithosphere and Still Life) found that another mod's overworld replaced the Vantraya world type; **0.1.1 fixes that**, and a second real run is still to be done — see [Troubleshooting](../README.md#troubleshooting) and "Not verified" in the [README](../README.md#status-and-known-limits). If something is wrong, `/vantraya where` and the lines of `latest.log` that start with `Vantraya:` are what is needed.

## Versions

* **0.1.2** — from the second play session: no more Nether structures in the overworld (the nether fortress by the caldera) and no structures standing in rivers; biome borders blend in patches instead of "very stark borders"; rivers and lakes carry real water up into the highlands (Y ≈ 150), so the continent can be travelled by water. New options `fillRivers` and `structurePolicy`.
* **0.1.1** — a data pack's own `minecraft:overworld` no longer replaces the Vantraya world type; `/vantraya where` and the log say which generator a world uses; optional `preselectWorldType` (client config, off by default); the mod now declares Minecraft 1.21.1 / NeoForge 21.1.x only.
* **0.1.0** — first build.
